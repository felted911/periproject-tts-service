# Refactoring Documentation

This directory contains guidelines and examples for refactoring code in the Peri project.

## Contents

- [Refactoring Guidelines](refactoring_guidelines.md) - Comprehensive guide on when and how to refactor code
- [Task List](task_list.md) - Current refactoring tasks prioritized by importance *(to be created)*
- [Case Studies](case_studies.md) - Examples of successful refactoring efforts *(to be created)*

## Purpose

The purpose of these documents is to:

1. Provide clear guidelines on when code requires refactoring
2. Establish consistent approaches to common refactoring scenarios
3. Document best practices specific to our project's architecture
4. Serve as a reference for code reviewers and developers

## Using These Guidelines

These guidelines should be referenced when:

- Reviewing pull requests that include refactoring
- Planning refactoring work
- Evaluating technical debt in the codebase
- Onboarding new team members

## Contributing

To contribute to these guidelines:

1. Submit a PR with your proposed changes
2. Include examples demonstrating the benefit of your suggestions
3. Reference industry best practices or books where applicable

## Additional Resources

For more information on refactoring, consider these resources:

- [Refactoring: Improving the Design of Existing Code](https://refactoring.com/) by Martin Fowler
- [Clean Code](https://www.oreilly.com/library/view/clean-code-a/9780136083238/) by Robert C. Martin
- [Working Effectively with Legacy Code](https://www.oreilly.com/library/view/working-effectively-with/0131177052/) by Michael Feathers
